# Trace 关联、项目级追踪与双向联动

状态：首版及原后续设计的项目级追踪、结构编辑、证据检查、增量分析、协作恢复和编辑器入口已实现。用户决策：双向建议、预览后应用；普通编辑只做本地影响检测，不自动调用模型或改写另一侧。

## 1. 与论文对应的方法

刘少英老师参与的《Improve Automatic Recovery of Trace Links from Natural Language Requirements to Formal Specifications with LLMs》采用：从需求分解树提取末级功能；通过语法及依赖分析组织 process 与关联声明；让 LLM 判断需求到 process 的对应关系。

Studio 的默认“全部 process（论文方法）”按上述对象分析：源端为末级 **function**，目标端为 **process**。选中父需求时展开其末级功能，不把类型、变量或 scenario 误当成论文中的独立功能候选。process 上下文包含递归类型、常量、变量、函数和相关不变量，并延伸到其他规格文件。显式已有来源直接记录；历史规格由语义恢复补关联。手动关联仍允许数据、约束和 scenario，以服务实际编辑。

论文 Table 2、9 的平均 Precision 99%、Recall 94%、F1 0.9625 来自论文四个项目共 48 个功能，**不是 Studio 的测量结果**。论文验证关联恢复，双向更新、冲突处理和恢复机制是 Studio 的产品扩展。三种概念保持独立：

- 关联审核：推荐、确认、拒绝。
- 变更状态：无变化、需求变化、规格变化、双方变化、端点丢失。
- 约束检查：未评估、部分缺失、有支持证据、可能矛盾。模型检查不是形式化证明。

## 2. 自然编辑流程

- Informal / Hybrid 工具栏提供“关联”入口，图形树、process 卡片和表单提供节点入口。
- 文档编辑器的标题旁显示关联计数。按钮是正文外的 Vue 浮层，不把标签写入 Markdown，不污染撤销记录。
- Monaco 的需求和规格节点上显示 CodeLens，点击即可打开对应关联；开启跟随后，代码光标也能筛选关联。
- 关联图按需求与规格分列，点击端点定位。推荐为虚线，待检查为黄色；可以隐藏，避免妨碍正常编辑。
- 面板支持项目 / 当前文件范围、搜索、节点选择、未关联、推荐、待检查、批量审核。默认不自动跳走当前查看位置。

旧项目：点击“AI 查找关联”，核对推荐依据与两侧原文后接受。新规格：应用规则生成器 / Agent 的生成提案时同时记录来源。无模型配置时，手动关联、定位、影响检测和撤销照常可用。

修改任一侧后，查看与上次检查的差异，选择更新方向，核对逐块预览和共享声明影响，再应用所选内容。完整应用仅推进当前关联的检查基线；部分应用保留待检查；其他共享声明关联仍需检查。“已检查，无需更新”要求填写说明。“稍后处理”只暂缓当前快照，出现新变化时重新提醒。普通保存不会清除待检查状态。

## 3. 项目索引与迁移

权威存储：`<project>/.agile-sofl/trace/workspace-v3.json`。磁盘封套版本为 3，内部图 DTO 保持兼容的 `version: 2`，增加可选 files、audit、migrations。schema 与接口在 `src/shared/traceability.ts` 和 `traceAdvanced.ts`。

每个文档有独立 document UUID、项目相对路径、历史路径别名、内容摘要与 present 状态。每个实体有独立 UUID、当前 locator、documentId / documentPath、原文、上下文、依赖 UUID 和当前字符范围。字符偏移只用于当前版本导航。

数据源取项目 manifest 与已打开文件，**未保存缓冲区优先于磁盘**。同一需求可关联不同文件的 process，切换模块共享同一图，不再复制需求身份。跨文件符号先找当前模块，再使用唯一外部声明；有歧义时不猜测。

文件移动且内容不变时，用唯一摘要恢复文档身份。移动同时修改时，在“更多操作 → 重新定位文件”中预览旧文件与新文件匹配数，再确认；不能唯一匹配的实体继续保留丢失状态，供逐条重关联。

旧版按文件对的 v2 图会汇入项目图，原文件保持不变。共享需求实体归并，UUID 冲突重新分配，审核决定 / 基线不一致的重复关系改为待确认并保留说明。`.aspec.trace.json` 中可唯一匹配的旧关联作为推荐导入。迁移记录在面板中可查看。损坏、不支持或越出项目的元数据返回错误，不静默覆盖。

## 4. 拆分、合并与重新分配

在“拆分 / 合并需求”中选择一个末级需求拆成多项，或多个同文件、同级、同类型的末级需求合为一项。先填写标题与描述并预览正文，再为每条旧关系选择新端点；可以一对多，解除则必须明确勾选。未分配的关系阻止应用。

结构预览按 revision 和全部源文本校验，生成后的新 UUID 固定保存在计划中。正文变化和重绑定一起进入全局历史，一次撤销 / 重做同时恢复正文与关系。合并后的重复关系保留来源说明并重新审核，不把几个旧基线自动当作一致。已有的删除、外部结构编辑也可使用“分配关联”，无需先删除另一侧正文。

`TraceRebindPlan` 明确记录 from、to、每条关系的 endpoint 与新 targets。`TraceStructurePreview` 记录原文快照、新正文、新实体和受影响的关联，应用只接受计划范围内的选择。

## 5. 证据、约束检查与评估

恢复提示要求模型提供 requirementFragment、specificationFragment、具体理由与缺失约束。只有实际存在于对应版本上下文中的引文才保存为验证证据；不能核对的引文不显示为证据，也不能把覆盖结论标为 supported。每条证据 / 检查结论携带基线；内容变化后显示“需重新检查”。

“检查约束”可独立于“接受关联”执行。界面展示缺失约束及模型检查标签，不用绿色关联数暗示语义满足。关系类型注册表区分 refines、constrains、uses，为其他工件接入保留契约；本次追踪目标仍是 Informal / Hybrid，没有将 GUI 触发边冒充需求形式化边。

离线评估入口：

```bash
# 在 packages/studio 中
npm run test:trace
node scripts/trace-evaluate.mjs tests/fixtures/trace-evaluation.json supplied
node scripts/trace-evaluate.mjs tests/fixtures/trace-evaluation.json name
node scripts/trace-evaluate.mjs tests/fixtures/trace-evaluation.json vsm 0.5
```

支持 supplied（模型或人工预测）、名称基线、词频 VSM、外部 embedding 向量基线。数据以 cases 划分项目，包含 requirements、processes、expected 与可选 predicted / vector。报告每项目、micro 与 macro Precision / Recall / F1，支持负例和多对多真实链接；相似度基线按论文比较方式选择最高分及阈值。向量必须来自研究者指定的模型，本工具不会把词频伪称为预训练 embedding。

附带数据是**合成回归样例**，不是论文数据集。真实模型质量、处理耗时与人工接受率应在独立标注的数据上测量，不能把测试替身的结果当成模型性能。模型调用、自动更新和形式化证明不混为一谈。

## 6. 增量分析、缓存与 provider

`TraceRecoveryProvider` / `TraceUpdateProvider` 与注册表允许接入不同模型；provider 只返回候选或建议，不拥有正文提交入口。默认使用 Studio 已配置模型，界面不要求用户维护 prompt 参数。

每个末级功能分别分析，缓存键包括 prompt 版本、provider、模型身份与完整需求 / 候选依赖上下文。输入不变时复用结果；声明、模型或提示版本变化使相应缓存失效。缓存只保存本地结果，不保存 API key，也不额外上传遥测。输出结构与端点先验证再入缓存，截断或无效结果不能污染后续运行。

默认全量 process 候选与论文相符。“缩小候选”是明确标注可能漏链的可选加速模式，保留全量回退。显示任务进度、候选数、缓存命中和估计上下文 token；估计不是账单或价格承诺。取消会中止请求并阻止后续批次，重新运行复用已完成缓存，无需重做已完成模型调用。

## 7. 协作、审核与恢复

项目图写入使用跨进程排他锁、expected revision 和同目录临时文件替换。失去写入权时提示刷新，不覆盖另一个窗口的审核决定。仅当持锁进程已不存在时回收锁。

“导出审核快照 / 对比审核快照”使用 base / local / remote 三方合并。实体、关系以 UUID 合并，独立新增和不冲突的决定可以组合；同一关系的拒绝与确认、重复端点的并发新增、并发文件移动等冲突需用户选择本地或导入版本。预览后又出现新审核会要求重做比较。导入审核不写规格正文，合并后的图会按本地真实源文件重新解析，外部版本的证据不能假装仍然有效。

审核日志记录 actor、时间、动作、受影响 link UUID 与 revision；不记录完整模型提示或凭据。撤销产生新的审核事件，不删除此前记录；本地保留最近 5000 条事件。

应用更新前写入 prepared 事务，保存正文缓冲区的 before / after 与元数据；正常应用后标记 buffers-applied。重开项目会显示中断或未保存更新，允许恢复到编辑器或保留当前内容。恢复若遇到第三种较新的内容会停止，不覆盖用户编辑。

“保存规格文件”是用户显式触发的、带持久日志的多文件保存：比较加载时保存基线、写入 prepared 日志、逐文件原子替换、标记 committed，并沿用模块 XML 导出。中途崩溃可根据日志恢复；这是一种**可恢复事务**，不是声称文件系统支持跨文件瞬时原子提交。普通 Ctrl+S 保留现有保存习惯，元数据独立保留检查基线。

## 8. 服务和编辑边界

- `trace-read/save`：项目解析、迁移、索引与版本化元数据。
- `trace-recover/suggest/assess/providers`：候选恢复、双向建议、约束检查与 provider 选择。
- `trace-prepare`：再次校验全部文档版本、所选块及依赖范围。跨文件建议返回 changes 数组。
- `trace-structure-preview/prepare`：正文结构与关联分配计划。
- `trace-stage/finish/transactions/restore/save-files`：应用日志、恢复和显式保存。
- `trace-merge`：审核三方合并；`trace-progress/cancel`：进度与中止。

建议只替换关联端点或它的声明依赖，不接受整文覆盖。派生 scenario 的更新作用于其所属 process，避免几个 scenario 共用一个谓词范围。重叠块、过期原文、结构越界、新增诊断、需要修复才能合法的代码都要求重新预览，实际应用必须与所见差异一致。持久化 IPC 返回后再次检查缓冲区，防止等待期间的新输入被覆盖。

## 9. 验证与复现

领域、服务与 store 测试覆盖：单侧 / 双侧 / 丢失状态；跨文件共享声明；未保存的非当前文件；唯一身份恢复与显式文件重定位；旧图迁移；锁与 revision；拆分合并；证据引文与失效；审核冲突；缓存与取消；正反向修改范围；中断恢复；保存失败和输入竞态；统一撤销重做。

文档浮层不修改 Vditor 正文；CodeLens/provider、事件与观察器随编辑器卸载释放。普通编辑不会触发模型调用。构建、模块边界检查、专项与完整 Studio 测试共同作为回归验证，仓库其余历史类型错误独立记录，不用它们掩盖 trace 的新增错误。
