# Trace：自动来源绑定与轻量变化提醒

当前交互定稿：系统维护 Informal / Hybrid 节点的对应关系；用户只处理另一侧发生的变化。日常界面不暴露接受、拒绝、检查、分配、重新关联、解除关联等管理操作。

## 1. 新项目与 Agent 建模

用户在项目中打开并保存 Informal / Hybrid 文件，Agent 基于 Informal 建模。新建语义节点必须带可解析的来源 ID 与完整目标 ID。模块空壳不要求虚构来源；scenario 和引用声明可以继承明确的 process 来源。

Agent 工具在产生新节点但遗漏来源时，会收到补齐来源并重试的反馈，不要求用户管理关联。源级修改同样支持 traceLinks。应用端用生成后的真实索引再次验证全部新增节点；缺失或歧义时，不写入正文。已有节点保留 UUID 和关联。

规格正文、来源绑定与事务日志一起应用，进入同一个全局撤销 / 重做操作。规则生成器通过 IR 中已知的 informalId 映射真实输出中的节点，包括变量、类型、process 和不变量，不依赖短名称模糊匹配。

来源绑定记录生成关系，不等同于证明生成内容正确。没有 Informal 来源的独立技术节点不能凭空关联到某个需求；需要 Agent 明确来源后再提交，或先完成项目中的需求建模。

## 2. 平时的编辑体验

- 条目有对应内容时才显示小型 ↔ 标记，不在每个未关联节点上展示按钮。
- 对方发生变化时，接收侧标记出现琥珀色圆点；正常输入只做本地检测，不调用 AI、不跳转、不弹窗。
- 点击节点标记，在当前位置打开变化卡片；点击对方名称可以定位。
- 标题旁浮层不写入 Markdown；Monaco CodeLens 使用相同的变化判断。
- 全局“对应内容”入口提供紧凑列表，默认收起，不展开大型管理台。

变化卡片只有三个日常动作：

| 动作 | 语义 |
|---|---|
| 已知晓 | 记录本侧已看过对方当前版本，收起本次提醒。不会推进同步基线，不声明两侧一致。对方再次修改时重新提醒。 |
| 手动修改 | 定位接收侧条目并回到现有编辑方式。用户可对照来源自行调整，不强迫完成额外审核步骤。 |
| AI 修改 | 生成对当前接收侧的建议，先预览修改前后内容、共享声明影响和理由，再勾选应用。 |

两侧都改过时，明确提示双方已有编辑；AI 的目标仍然是当前侧，预览中核对已有修改。部分应用不清除剩余影响；完整应用推进本条对应关系的同步基线，避免相同修改立即形成反向提醒。其他受影响关系仍独立检测。

已知晓按接收侧分别存储 `acknowledged.informal / acknowledged.hybrid`。判断提醒时只比较上游一侧的当前内容与同步基线、知晓快照，避免用户修改本侧时反复提醒自己。

## 3. 与论文方法的关系

论文《Improve Automatic Recovery of Trace Links from Natural Language Requirements to Formal Specifications with LLMs》针对已有工件恢复关联：提取末级功能需求，组织 process 与声明依赖上下文，再进行生成式语义匹配。

旧项目的“已有规格尚未记录来源？”入口保留该方法，默认候选为全部 process；用户主动触发分析后系统维护结果。新项目优先保留建模操作中的显式来源，不再走“生成之后重新猜来源”的常规流程。

论文中的准确率属于论文的实验数据；本系统没有复现其真实模型指标。关联存在、内容有变化、模型认为约束受到支持、形式化证明是不同概念。证据与约束服务保留在底层，不强迫用户每次编辑逐项检查。

## 4. 身份、保存与恢复

权威数据位于 `<project>/.agile-sofl/trace/workspace-v3.json`，磁盘版本 3，内部 DTO version 2 兼容原图。文档和实体有独立 UUID，路径、标题及字符位置不作为唯一身份。未保存缓冲区优先于磁盘。

唯一内容摘要支持文件移动后的身份恢复，可视化改名操作传递明确身份提示。依赖索引跨规格文件，共享声明的变化会影响相应 process。任意外部重构不能保证仅靠语义猜测正确重绑定；无法确定的关系保留历史身份，不静默连到另一个同名对象。

应用前检查源文本及图 revision，过期建议不覆盖新输入。图写入使用跨进程锁和原子替换。应用及多文件保存有持久事务日志，中断后可恢复到编辑器；这不是文件系统级跨文件瞬时原子提交。

模型调用可取消并缓存已完成结果。普通 Ctrl+S 不把提醒当成已知晓。审核历史、三方图合并、结构重绑定和评估服务仍保留为内部能力，日常 UI 不再堆放这些管理按钮。

## 5. 实现入口

- `shared/traceInteraction.ts`：接收侧提醒判断、生成来源解析与完整性校验。
- `renderer/stores/traceability.ts`：变化快照、知晓、导航、生成提交与统一历史。
- `TraceBadge.vue`：节点标记、定位弹层、Escape 和点击外部关闭。
- `TraceChangeCard.vue` / `TraceUpdatePreview.vue`：三个动作与应用前预览。
- `TraceWorkbench.vue`：紧凑全局入口、旧项目初始化和中断恢复。
- `main/services/traceEngine.ts`：节点身份、上下文、依赖和规则生成来源转换。
- `main/services/llm/agentLoop.ts` / `skills.ts`：Agent 来源契约与工具反馈。

## 6. 验证

`npm run test:trace` 覆盖提醒方向、双方修改、知晓后再变更、原文基线保持、缺失来源拒绝、生成事务撤销、文件写入失败和等待期间输入竞态。完整 Studio 测试同时验证原有编辑及 Agent 流程。

浏览器隔离 fixture 使用真实 Vue 组件和 store，模型与文件服务为测试替身；用于验证默认收起、三个动作、预览前不写入、应用后提醒消退和撤销恢复。它不是实际模型效果演示。

离线评估脚本 `scripts/trace-evaluate.mjs` 支持 supplied / name / VSM / embeddings。附带数据是合成回归样例，不是论文数据集。

实际演示与组会讲解见 [27-Trace演示与组会讲解.md](./27-Trace演示与组会讲解.md)。
